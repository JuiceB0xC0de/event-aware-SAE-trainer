## 2025-03-08 - Avoid repeated float casting and tensor subtraction in tight training loops
**Learning:** In PyTorch tight training loops, avoid recomputing identical float castings and subtractions (e.g., `acts_mb.float() - x_hat.float()`). Computing it once and saving it to a variable, then using `.detach()` where gradients are not needed, yields significant performance gains.
**Action:** Always look for repeated expensive operations (like dtype casting and element-wise arithmetic) inside the innermost loops and cache their results to reuse them.
## 2025-03-08 - Use `torch.where` and `dtype=float` in reductions instead of boolean casting
**Learning:** In PyTorch, applying a boolean mask by casting it to a float type and performing an element-wise multiplication (e.g., `(pre > threshold).to(pre.dtype) * grad_output`) scales linearly with the entire tensor size. Using `torch.where(mask, grad_output, 0.0)` is faster and avoids an unnecessary large float tensor allocation. Similarly, performing a sum operation and then casting its result via `.float()` creates an intermediate accumulation that can lose precision and is slower; using `.sum(dtype=torch.float32)` accumulates the sum directly in the required precision, which avoids an intermediate representation cast and saves time.
**Action:** When conditionally assigning or keeping gradients, use `torch.where` with a boolean mask instead of casting and multiplying. Furthermore, explicitly pass the `dtype` parameter in reduction operations (like `sum` or `mean`) instead of calling the reduction and then using a type conversion method like `.float()`.

## 2025-03-09 - Combine PyTorch Custom Autograd Functions with Shared State
**Learning:** In PyTorch, applying multiple custom autograd functions to the same inputs forces the framework to compute identical intermediate values multiple times and create parallel computational graphs. In this case, `_JumpReLU` and `_L0Indicator` were computing identical thresholds and threshold masks.
**Action:** When multiple operations share identical internal calculations on the same forward pass inputs, coalesce them into a single custom `torch.autograd.Function` that returns multiple values. The backward pass can then combine gradients linearly (e.g., `combined_grad = pre * grad_feat + grad_gate`) to execute the update in a single pass, saving significant time and memory.
